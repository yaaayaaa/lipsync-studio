# zunda-lipsync 設計書

- 日付: 2026-10-19
- 状態: 初版（最初の小さなリリースの範囲）
- 公開: OSS（MIT ライセンス）

## 1. 何を作るか・なぜ作るか

VOICEVOX の音声に合わせて、ずんだもんなどの立ち絵が口パクする「動画編集用の素材 mp4」を作る Web アプリ。

既存の作業の困りごとを解決するためのツールではなく、**リップシンクを軸にした新規プロジェクト**として始める。最初は小さく作り、OSS として公開して育てる。

ユーザーの流れは次のとおり。

1. 自分の PSD 立ち絵をアプリに追加する（PSDTool と同じ感覚で表情を選ぶ）
2. 口レイヤーを母音（あ・い・う・え・お・閉じ）に割り当てる
3. セリフを入力する
4. 立ち絵が喋る、音声付きでグリーンバックの mp4 を受け取り、自分の動画編集ソフトに載せる

## 2. 前提と制約

- **VOICEVOX はユーザーの PC で動かす。** アプリはブラウザからユーザーの VOICEVOX エンジン（既定は `http://localhost:50021`）に直接リクエストする。こちらで音声合成サーバーは用意しない。
- **配布方法はまだ決めない（ユーザー決定）。** 当面はリポジトリの開発サーバー（`npm run dev`）を `localhost` で開いて動かせればよい。VOICEVOX エンジンの既定の CORS 設定（`localapps`）は `localhost` と `127.0.0.1` からのリクエストを許可しているので、この形なら CORS の設定はいらない。将来は公開 URL での配布や、ネイティブアプリ化（Tauri など）もありうる。そのため次の2点を守る。
  - VOICEVOX との通信、PSD の処理、リップシンクの計算、エンコードは、React の UI から切り離したモジュールにする
  - エンジンの URL は設定で変えられるようにする
- **サーバーを持たない静的アプリにする。** PSD・音声・動画の処理はすべてブラウザ内で行い、PSD を外部へ送らない。
- **ffmpeg などの外部ツールを必要としない。**
- **立ち絵素材をリポジトリに同梱しない。** PSD はユーザーが自分で用意する。素材の利用規約を守るのはユーザーの責任で、README にもそう書く。

## 3. 目的・目的外・避けたいこと

### 目的（最初の版）

- PSD を読み込み、PSDTool と同じ規則でレイヤーを選んで表情を作る
- PSDTool のお気に入りファイル（`.pfv`）を読み込み、表情として取り込む
- 1つのキャラに、PSD・VOICEVOX の声・複数の表情・口の割り当てをまとめて保存する
- セリフをリストで編集する。行ごとにキャラ・表情・話速を選ぶ
- 行ごとにグリーンバックで音声付きの mp4 を書き出す

### 目的外（最初の版ではやらない。あとの版の候補）

- 抑揚・音高・音量・前後の間の調整、アクセントの編集
- 全行をつないだ1本の mp4 の書き出し
- 透過動画（WebM・MOV）の書き出し
- まばたきや体の揺れなど、口以外の動き
- 表情ごとに違う口レイヤーを使う割り当て
- 立ち絵の位置を自由に動かすこと、1画面に複数キャラを出すこと
- 字幕の焼き込み
- 音声合成サーバーのホスティング、ユーザーアカウント
- 配布の仕組み（GitHub Pages への公開、ネイティブアプリ化、インストーラー）

### 避けたいこと（技術的に動いても失敗とみなす）

- 口の動きが音声とずれて見える（とくに話速を変えたとき）
- PSD やセリフがユーザーの PC の外へ送られる
- 動かすのに、VOICEVOX と開発用の Node.js のほかに、サーバーの構築や追加ソフトが必要になる

## 4. 画面と機能

### 4.1 キャラ設定画面（3列レイアウト・ユーザー決定）

1画面に3列を並べ、すべて常に表示する（PSDTool 風）。

- **左列：レイヤーツリー。** PSD のグループとレイヤーを木構造で表示する。チェックボックス（`*` 付きはラジオボタン）で表示を切り替える。各行の名前の左に縮小画像を出す（PSDTool 風。レイヤーはその画像の透明な余白を除いて枠いっぱいに、グループは今の表示状態で中身を合成したものを出す）。
- **中央列：プレビュー。** 現在のレイヤーの組み合わせで合成した立ち絵を表示する。
- **右列：口の割り当てと表情の一覧。**
  - 口レイヤーが入っているグループ（「口グループ」）を1つ指定する（縮小画像付きのドロップダウンで選ぶ）
  - 「あ・い・う・え・お・閉じ」のそれぞれに、口グループ直下のレイヤーから1つを縮小画像付きのドロップダウンで選ぶ（名前だけでは見分けにくく、タイルを並べると多すぎるため。ユーザー決定）
  - 「あいうえお」を再生するボタンで、割り当てをその場で確認できる
  - 口を編集している間、中央のプレビューは編集中の母音に自動で切り替わり、ドロップダウンで強調中の口を保存前に試し見せする。口グループを変えると「閉じ」（未設定なら最初に割り当てた母音）、ツリーを操作すると「閉じ」に戻る。プレビューの切り替えは「閉じ・あ・い・う・え・お」で、既定は「閉じ」（「ツリーのまま」は廃止。口が未割り当てならツリーの状態がそのまま映る）（ユーザー決定）
  - 表情の一覧から、現在のレイヤー状態を名前付きの表情として保存・上書き・削除できる
  - `.pfv` を読み込むと、そのお気に入りを表情として一括で追加する
  - VOICEVOX の話者とスタイルを選ぶ（このキャラの声）

キャラについてのルールは次のとおり（ユーザー確認済み）。

- 同じ口レイヤーを複数の母音に割り当ててよい（口のパターンが少ない素材に対応するため）
- 「ん」と無音のときは「閉じ」の口を使う
- 口の割り当てはキャラごとに1つで、どの表情でも共通
- 口は、表示中の表情のレイヤー状態の上で切り替える。そのとき口グループ直下のレイヤーはすべて隠し、割り当てた口だけを表示する。表情や `.pfv` に割り当て外の口が入っていても、口が2つ重ならないようにするため（私の判断）
- 口が複数のグループに分かれている PSD は、最初の版では扱わない（私の判断）

### 4.2 PSDTool 互換（ユーザー決定：規則の再現と `.pfv` の読み込みの両方）

PSDTool のマニュアル（https://oov.github.io/psdtool/manual.html ）に従う。

- レイヤー名が `*` で始まる場合は、ラジオボタンとして扱う。同じ親の中で `*` 付きのものは1つだけ表示する。選択の解除はできない。
- レイヤー名が `!` で始まる場合は、常に表示する。チェックボックスを出さない。
- 名前の末尾が `:flipx`・`:flipy`・`:flipxy` のレイヤーは、反転表示のときだけ使う。最初の版は反転機能を持たないので、これらは**常に非表示にし、ツリーにも出さない**。
- `.pfv` の形式は次のとおり。
  - UTF-8（BOM なし）・LF の文字列で、1行目は `[PSDToolFavorites-v1]`
  - `//フォルダ/名前` の行で1つのお気に入りが始まり、続く行にレイヤー状態を書く
  - レイヤー状態は、表示中のレイヤーを `/` 区切りのパスで列挙したもの
  - 同じ階層に同じ名前があるときは `\N`（下から数えた番号）で区別する
  - 名前は独自の URL エンコード（`%xx`）をしている
  - `~folder` や `~filter` などのマーカーが付いた行と、未知のマーカーの行は読み飛ばす
- `.pfv` の中に今の PSD に存在しないレイヤーがあるときは、その行を無視する。取り込み後に件数を表示する（例：「12件取り込み、2件のレイヤーが見つかりませんでした」）。

### 4.3 セリフ編集画面

セリフを縦のリストとして並べる。1行に持つものは次のとおり。

- テキスト
- キャラ（選ぶと声と立ち絵が一緒に切り替わる）
- 表情（そのキャラの表情から選ぶ）
- 話速（VOICEVOX の `speedScale`。範囲は 0.5〜2.0、既定は 1.0）
- 試聴ボタン（音声だけを再生する）
- プレビュー（その行の口パクを、画面上で音声付きで再生する）
- 書き出しボタン（その行の mp4 を作る）

行の追加・削除・並べ替えができる。「全行を書き出す」ボタンも置く。

### 4.4 書き出し（ユーザー決定：グリーンバックの mp4・1行ごとに1本）

- 映像は H.264、音声は AAC で、mp4 コンテナに入れる
- 背景は単色で、既定はグリーン（`#00FF00`）。色は書き出し設定で変えられる。ずんだもんは髪や枝豆が緑なので、クロマキーで体の一部まで抜けることがあるため（私の判断）
- 立ち絵は画面中央に固定する。解像度（1920×1080 など）と立ち絵の拡大率は、書き出し設定で選ぶ
- 動画の長さは、その行の音声の長さと同じにする

## 5. リップシンクの仕組み

1. VOICEVOX の `POST /audio_query`（`text`・`speaker`）でクエリを取得し、`speedScale` を行の値に書き換える
2. 同じクエリで `POST /synthesis` を呼び、WAV を取得する
3. クエリの `prePhonemeLength`、各 `accent_phrases[].moras[]` の `consonant_length` と `vowel_length`、`pause_mora`、`postPhonemeLength` から、母音のタイムラインを組み立てる
   - **各長さは `speedScale` で割って実時間にする。** 生成された WAV の長さと、組み立てたタイムラインの総時間が一致することをテストで確かめる（避けたいこと「口がずれる」への対策）。
4. 母音を口に対応させる
   - `a`・`i`・`u`・`e`・`o` は、そのままあ・い・う・え・お
   - 無声化母音（`A`・`I`・`U`・`E`・`O`）は、対応する母音
   - `N`・`cl`・`pau`・前後の無音は「閉じ」
5. 映像のフレームごとに、その時刻の口を選んで合成する

## 6. 技術構成（私の判断。ユーザーが了承）

- Vite + React + TypeScript による静的 SPA
- PSD の読み込みは `ag-psd`
- PSDTool の規則と `.pfv` の解析は自前で実装する
- 映像と音声のエンコードはブラウザ標準の WebCodecs（`VideoEncoder`・`AudioEncoder`）を使う。mp4 へのまとめには、`mp4-muxer` の後継である **Mediabunny** を使う。ユーザーには `mp4-muxer` と伝えていたが、`mp4-muxer` は作者が非推奨にして Mediabunny へ移行しているため、こちらで差し替えた。
- テストは Vitest

## 7. 私の判断（ユーザー未確認。違えば直す）

- **対応環境は、Windows と macOS の Chrome・Edge のデスクトップ版に絞る。** WebCodecs で AAC と H.264 のエンコードが使えるため。Linux 版の Chrome は AAC をエンコードできないので、最初の版では対象外にする。起動時に `VideoEncoder.isConfigSupported` と `AudioEncoder.isConfigSupported` で確かめ、非対応ならそう表示する。
- **フレームレートは 30fps 固定。**
- **保存先はブラウザの IndexedDB。** キャラ（PSD 本体を含む）とセリフのリストを自動保存する。キャラ設定の書き出し・読み込み（ファイルでの共有）は、あとの版にする。
- **「全行を書き出す」は zip にまとめて1回でダウンロードする。** ファイル名は `001_キャラ名_セリフ先頭10文字.mp4`。
- **VOICEVOX のクレジットを表示する。** 書き出し後、使った話者のクレジット文字列（例：「VOICEVOX:ずんだもん」）を表示し、コピーできるようにする。VOICEVOX の音声は、キャラごとにクレジット表記が必要なため。
- **VOICEVOX につながらないときは、画面上部に案内を出す。** 起動しているか、URL は正しいか、CORS の設定はどうか、を確認するよう促す。エンジンの URL は設定で変えられる。通信にはタイムアウトを付け、失敗したら行ごとにエラーを表示する。

## 8. 作る人に任せること

- 子音の区間の口の形。最初は、そのモーラの母音の口でよい。m・b・p のときだけ閉じるかどうかなどは、見た目で判断する。
- 画面の細かな見た目と配色
- PSD の合成処理の実装方法（合成モード、マスク、クリッピングにどこまで対応するか）。ただし、一般的なずんだもんの立ち絵 PSD が PSDTool と同じ見た目になることを目標にする。
- mp4 のビットレートなどのエンコード設定
- 状態管理やディレクトリ構成

## 9. テスト方針

- 単体テストは次の4つ
  - `.pfv` の解析（エンコードされた名前、同名レイヤーの `\N`、マーカー付きの行の読み飛ばし）
  - PSDTool の規則（`*` のラジオ、`!` の常時表示、`:flip*` を隠す）
  - モーラから母音タイムラインへの変換（話速を変えたときの総時間を含む）
  - 母音から口への対応
- VOICEVOX との通信は、スタブに差し替えてテストする。接続の失敗とタイムアウトも含める。
- 実機での確認として、実際の VOICEVOX とずんだもんの PSD で mp4 を書き出し、動画編集ソフトでグリーンバックが抜けること、口と音声が合っていることを目で確かめる。
