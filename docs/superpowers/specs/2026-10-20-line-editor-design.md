# 1行編集画面 設計書

- 日付: 2026-10-20
- 状態: 初版
- 前提: [zunda-lipsync 設計書](2026-10-19-zunda-lipsync-design.md) の上に足す機能。矛盾したときはこちらを優先する

## 1. 何を作るか・なぜ作るか

声の仕上がりにこだわる人のための、**セリフ1行を VOICEVOX と同じ細かさで作り込む画面**を足す（ユーザー決定）。

想定する使い方は、1行ずつ声を作り込み、口パク付きのプレビューで確かめ、納得したらその1本の mp4 を書き出して動画編集ソフトに貼っていく流れ（ユーザーの言葉：「1行ずつ確認しながら動画編集ソフトに貼っていくとき。音声の生成にこだわる人」）。

今の「セリフ」画面はまとめて流し込む用途に向いていて、行ごとに選べるのは話速だけ。最初の設計書で「目的外」にしていた抑揚・音高・音量・前後の間・アクセントの調整を、この画面で入れる。

## 2. 目的・目的外・避けたいこと

### 目的

- VOICEVOX が1行の音声として持つ調整をすべてできる（ユーザー決定：「VOICEVOX の全部のカスタムをできる前提」）。中身は 4.3 節
- 作り込んだ内容は「セリフ」の一覧と同じ行に保存し、一覧側の試聴・プレビュー・書き出し・全行書き出しにもそのまま効く（ユーザー決定）
- 編集した内容で、口パク付きのプレビューを再生して確かめられる
- その行の mp4 を1本ダウンロードできる

### 目的外（今回はやらない）

私の判断。必要になったら次の版で足す。

- プリセット（調整値に名前を付けて使い回す）
- モーフィング（2つの声を混ぜる）
- ユーザー辞書の編集（VOICEVOX 本体でできる）
- 歌の機能
- 保存先フォルダへの直接保存・編集ソフトへのドラッグ（ユーザー決定：ダウンロードでよい）

### 避けたいこと

ユーザーに聞いたら「わからない」だったので、私が置いた基準。

- 調整した結果、口パクが音とずれる
- 画面を切り替える・再読み込みすると作り込みが消える
- 数値を動かすたびに長く待たされて、確かめながら調整できない
- アクセントや区切りの直し方が VOICEVOX と違って、慣れた人が迷う
- 「セリフ」の一覧とこの画面とで、キャラ・スタイル・話速などの内容が食い違う

## 3. データ

### 3.1 行に持たせるもの

`ScriptLine` に、作り込んだ内容 `tuning` を任意で持たせる。

- `tuning` がない行は今までどおり：再生や書き出しのたびに `audio_query` からクエリを作り、`speedScale` だけ行の値にする
- `tuning` がある行は、保存したクエリ（アクセント句と全体の数値）をそのまま合成に使う。`audio_query` は呼ばない
- `tuning` は、作ったときの**セリフの文**と**スタイル ID（声）**を一緒に覚える。今の行の文や声と合わないときの扱いは 3.2 節
- 全体の数値のうち話速は、今ある `ScriptLine.speedScale` を唯一の置き場にする。一覧の話速とこの画面の話速は同じ値を指す（食い違いを作らないため）。それ以外の全体の数値（音高・抑揚・音量・間の倍率・開始/終了の無音）は `tuning` に入れる
- 書き出し時に強制で上書きしている値（`outputSamplingRate` 48000、`outputStereo` false）は保存しない。合成の直前にいつもどおり付ける

保存先は今と同じ IndexedDB の `kv` のセリフ一覧。古いデータ（`tuning` のない行）はそのまま読める。

### 3.2 合わなくなったとき

- **セリフの文を変えた**（どちらの画面で変えても）：その行の `tuning` を捨てる（ユーザー決定。VOICEVOX と同じ挙動）。全体の数値も一緒に既定値へ戻る。話速は行の値なので残る
  - 1文字打つたびに捨てると、打ち間違い1つで作り込みが消える。そこで `tuning` のある行だけは、文の確定（フォーカスを外す・Enter）の時点で「作り込みが消えます」と確認を出し、取りやめたら文を元に戻す（私の判断）。`tuning` のない行は今までどおり打つたびに保存する
  - 1行編集画面では、文の変更も取り消し（Ctrl/Cmd+Z）の対象にし、捨てた `tuning` ごと戻せるようにする（私の判断）
- **声（スタイル ID）が変わった**：アクセントの位置・区切り・読みは残し、`/mora_data` を新しい声で呼び直して高さと長さを作り直す。手で動かした高さと長さは失われる（私の判断。声が変わると高さの基準が変わるため。VOICEVOX も声を変えると高さと長さを取り直す）。全体の数値は残す
  - 声が変わる経路は2つある：行のキャラを変えたときと、「キャラ設定」でキャラの声を変えたとき（そのキャラの全行に効く）。どちらも、変えた瞬間ではなく**合成に使う直前**（再生・プレビュー・書き出し・1行編集で開いたとき）に `tuning` の声と今の声を比べて取り直す（私の判断）。取り直した結果は `tuning` に保存する
  - 取り直したら、1行編集画面にその旨を1行で出す（「声が変わったので高さと長さを取り直しました」）。一覧や全行書き出しでは知らせない
  - エンジンにつながらず取り直せないときは、合成もできないので、今の合成失敗と同じく行ごとのエラーにする
- **キャラやスタイル（立ち絵）だけを変え、声は同じ**：何もしない

## 4. 画面

### 4.1 置き場所（ユーザー決定：A 案）

画面上部の切り替えに「1行編集」を足し、「キャラ設定」「セリフ」「1行編集」の3つにする。

```
┌────────────┬──────────────────────────────┬──────────────┐
│ 行の一覧    │ 文の入力・キャラ・スタイル     │ 全体の数値     │
│ 1 こんにちは│ ┌──────────────────────────┐ │ 話速          │
│▶2 ずんだ…  │ │  口パク付きプレビュー       │ │ 音高          │
│ 3 今日は…  │ └──────────────────────────┘ │ 抑揚          │
│ ＋行を追加  │ [アクセント|高さ|長さ]  ▶再生 │ 音量          │
│            │  ズンダモンナノダ（句ごと）    │ 間の倍率       │
│            │  [この行を書き出し]           │ 開始/終了の無音 │
└────────────┴──────────────────────────────┴──────────────┘
```

- 左：「セリフ」と同じ行の一覧。選んだ行を中央と右で編集する。行の追加もできる。並べ替えと削除は「セリフ」画面でやればよい（私の判断）
- 中央上：セリフの文、キャラ、スタイルの選択。一覧の行と同じ値を編集する
- 中央：口パク付きのプレビュー（今のプレビューと同じく、書き出しと同じ配置・背景色）
- 中央下：アクセント句の編集欄。「アクセント」「高さ」「長さ」をタブで切り替える。再生ボタンと「この行を書き出し」もここ
- 右：全体の数値

「セリフ」画面の一覧からも、行をこの画面で開けるようにする（行の操作に「1行編集で開く」）。

### 4.2 一覧と選択

- どの行を開いているかは画面を切り替えても覚えておく。開いている行が消されたら、未選択の状態にする
- 一覧の各行には、その行に `tuning` があるか（作り込み済みか）が分かる小さな印を付ける（私の判断）

### 4.3 編集できること

VOICEVOX エディタの操作に合わせる。エンジンの API は次の4つを使う：`/accent_phrases`（`text`・`speaker`・`is_kana`）、`/mora_data`、`/synthesis`、`/audio_query`（`tuning` を初めて作るとき）。

| 操作 | 振る舞い |
|---|---|
| アクセントの位置 | 句ごとに、どのモーラでアクセントが下がるかを選ぶ。変えた句だけ `/mora_data` で高さと長さを取り直す |
| アクセント句の区切り | モーラの間をクリックすると句を分け、句の境目をクリックするとつなぐ。変わった句だけ `/mora_data` で取り直す |
| 読み | 句を選んでカタカナの読みを直す。入力はただのカタカナで、アプリが元のアクセント位置（モーラ数を超えたら最後のモーラ）を AquesTalk 風記法の `'` として付けてから `/accent_phrases?is_kana=true` に渡す（VOICEVOX エディタと同じ）。結果が複数の句になったら、そのまま区切り直しとして受け入れる。読みが不正なときはエンジンのエラー文を出して元のまま |
| 高さ | モーラごとの `pitch` を動かす。無声のモーラ（高さ 0）は動かせない |
| 長さ | モーラごとの子音の長さと母音の長さ、句の後ろの無音（`pause_mora`）の長さを動かす |
| 全体の数値 | 話速・音高・抑揚・音量・間の倍率・開始の無音・終了の無音 |

- 範囲は VOICEVOX エディタに合わせる。話速だけは一覧と同じ 0.5〜2.0 にそろえる
- **既定値は、エンジンの `/audio_query` が返した値**とする（私の判断）。`tuning` を作るときは `/audio_query` の結果から始めるので、最初にどこかを動かしても他の値は変わらない
- 全体の数値は VOICEVOX エディタが画面に出しているものに限る（間は倍率 `pauseLengthScale` だけ。絶対値の `pauseLength` は扱わない）。疑問形の語尾上げ（`is_interrogative`）は、エディタと同じく文末の「？」で決まり、個別には切り替えない（私の判断）
- 最初にどこかを動かした時点で `tuning` を作る。開いただけでは作らない
- 「元に戻す」ボタンを置き、その行の `tuning` を捨てて自動の状態（`/audio_query` の結果）に戻せるようにする。これも取り消しの対象
- 取り消し（Ctrl/Cmd+Z）とやり直し（Ctrl/Cmd+Shift+Z）を、この画面の編集に対して効かせる（私の判断。VOICEVOX にもあり、作り込む人には必須と考える）。履歴は開いている行ごと・ページを開いている間だけでよい

### 4.4 再生と待ち時間

- 再生ボタンで、今の内容で合成して、プレビューの口パク付きで鳴らす
- 数値を動かすたびに自動で合成はしない（私の判断。CPU 版のエンジンだと合成に秒単位かかり、動かすたびに待たされるため）。再生を押したときだけ合成する
- 合成結果のキャッシュ（`SpeechCache`）の鍵を、文・声・話速から「合成に使うクエリ全体＋声」に変える。同じ内容なら合成し直さない。`tuning` のない行は今と同じ鍵の考え方でよい

### 4.5 書き出し

- 「この行を書き出し」で mp4 を1本ダウンロードする
- ファイル名は `<セリフ先頭10文字>_<ID8文字>.mp4`。ID は書き出すたびに新しく作る（ユーザー決定）。例：`ずんだもんなのだ！ぼく_3f9a1c2e.mp4`
- 「セリフ」画面の行ごとの書き出しも同じ名前の付け方に変える（私の判断。単体のダウンロードの名前をそろえる）
- 全行書き出しの zip の中身は今の `001_キャラ名_先頭10文字.mp4` のまま（私の判断。番号順に並ぶほうが一括で貼りやすい）
- ファイル名に使えない文字の扱いは今の `naming.ts` と同じ

## 5. リップシンク

- 口のタイムラインは、今と同じく合成に使ったクエリから作る（`buildMouthTimeline`）。手で長さを変えても、合成に使うクエリから作るので口は自動で合う
- 実エンジンでの照合スクリプト（`scripts/check-timeline.ts`）に、長さ・間・前後の無音・間の倍率を手で変えたクエリの例を足し、ずれが出ないことを確かめる

## 6. 作る人に任せること

- 編集欄の見た目と操作（棒グラフをドラッグするか、つまみか、数値入力を併用するか）。VOICEVOX エディタを参考にする
- 句が多くて横に収まらないときのスクロールの仕方
- 取り消し履歴の持ち方

## 7. テスト方針

- `tuning` の作成・文の変更での破棄・声の変更での取り直し（スタブのエンジンで）
- アクセント・区切り・読みの変更が、変わった句だけ取り直すこと
- 合成に使うクエリ（`tuning` あり／なし）の組み立て。出力の固定値を付けること、話速が行の値であること
- 合成キャッシュの鍵が、クエリのどこかが変われば変わること
- 単体ダウンロードのファイル名（10文字の切り詰め・使えない文字・ID 8文字）
- 古い保存データ（`tuning` なし）を読めること
- 実エンジンでの照合（5節）
