### 終端の長さと瞬き（Task 3〜6）

2026-10-20、Chrome（ヘッドレス、playwright-core）で確認した。書き出し・プレビュー・行ごとの終端（Task 3・4・6）と、下の「最終確認」は本物のエンジン 0.25.2 につないで行った。目の割り当て（Task 5）はエンジンを使っていない。立ち絵は特に断りがなければ `samples/sample.psd`。本物のずんだもん PSD で確かめたのは、目の割り当て（Task 5）だけ。フレーム番号は 0 始まり（先頭のフレームが 0、30fps なので N 番は N/30 秒から）。

- 書き出し（Task 3）：終端 0・目の割り当てなしの mp4 は、変更前と変更後でフレームが全部一致（framemd5、84 フレーム）。終端 2 秒で正確に 60 フレーム増え、音声の長さは変わらない。閉じ目だけ割り当てた瞬きは、0 始まりで 31〜33 番のフレーム（1.03〜1.13 秒）が閉じ目だった
- プレビュー（Task 4）：「セリフ」のプレビューと「1行編集」の再生で、最初の約 2 秒後に瞬きし、以後 3〜4 秒おきに閉じて開く
- 瞬きのスイッチ：サンプル PSD でライト・ダークとも、初めはオン、オフにすると欄が見出しだけに畳まれ（開いていたドロップダウンも閉じる）、「瞬き」ボタンが押せなくなり、オンに戻すと目の割り当てが残っている、再読み込み後もオフのまま、キーボード（Space）でオンに戻せることを確認した。オフのキャラが書き出しで瞬きしないことは単体テスト（`blinkSpec`・`FrameStore`）で確かめた
- 目の割り当て（Task 5）：サンプル PSD でライト・ダークとも、グループと閉じ目の選択、「瞬き」ボタン（開く→閉じる→開く）、再読み込み後も保たれることを確認した。本物の `ずんだもん立ち絵素材2.3.psd`（グループ `目`、閉じ目 UU）でも、瞬きで 開く→閉じる→開く になった
- 行ごとの終端（Task 6）：スライダーで「この行だけ」になり、取り消しで「既定」に戻り、やり直しもできる。「既定に戻す」で保存データから項目が消える。「設定」の既定を変えると表示も変わる
- 最終確認（半目・入れ子のグループ）：`samples/sample.psd` の目のグループは子が 2 つ（普通目・にっこり）しかなく、半目を当てても開き目と見分けられない。そこで同じスクリプトをもとに、`顔` グループの中に `目`（子：`飾り` グループ・普通目・にっこり・半目、色はそれぞれ別）と `口`（子：`内側` グループ・4 つの口）を入れた PSD を作って使った。閉じ目に `にっこり`、半目に `半目` を割り当て、約 12 秒の行に終端 3 秒を付けた
  - 書き出し：454 フレームの目の位置の色を ffmpeg で取り出して判定し、`eyeSchedule`（行の id・454 フレーム・半目あり）と全フレーム一致。瞬きは 0 始まりで 82・193・315・444 番から始まり、どれも 半目→閉じ目→閉じ目→半目 の順だった
  - プレビュー：「セリフ」のプレビューと「1行編集」の再生をそれぞれ約 26 秒、描画のたび（約 1560 回）にキャンバスを調べた。最初に描かれてから後、背景だけの絵は 0 回（立ち絵が消えることはない）。どちらも 3 回瞬きし、毎回 半目→閉じ目→半目 と変わった。瞬きの間隔（約 3.7 秒・約 4.1 秒）は書き出しの 111・122 フレームと合う
  - グループの候補：口グループに `顔/口` を選ぶと、目のグループの候補は `顔/目`・`顔/目/飾り` だけになる（`顔/口` 自身・祖先の `顔`・子孫の `顔/口/内側` が外れる）。目のグループに `顔/目` を選ぶと、口グループの候補は `顔/口`・`顔/口/内側` だけになる。この確認で、祖先を外すとその中の兄弟グループまで候補から消える不具合が見つかり、直した

## 既知の制限

- スタイルで初めから目を閉じた形の行も、瞬きの間は割り当てた閉じ目になる
- 動画の終わりで途中までしか入らない瞬きは入れない（瞬き1回の 4 フレームが収まらなければ省く。半目なしの 3 フレームの瞬きでも同じ基準）
- 合成した音声は（セリフ・声・話速。作り込んだ行はクエリ全体と声）ごとにページを開いている間だけ覚えて使い回す（上限 64MB）。VOICEVOX 側でユーザー辞書を変えたときは、ページを再読み込みするまで古い読みのまま
- レイヤーマスクは未対応
- クリッピングされたレイヤーは、自分自身の描画モードを無視する（例：乗算の影が通常描画になる）
- 未対応の描画モードのレイヤーは、通常描画になる
- 口が複数のグループに分かれている PSD は未対応
- Linux 版 Chrome は対象外（AAC をエンコードできないため）。実行時に `canEncodeAudio` で判定し、非対応なら画面に表示する
- 「キャラ設定」で「あいうえお」を再生中に「セリフ」画面へ切り替えても、再生は約2秒で終わるまで止まらない（両方の画面を表示したまま保持しているため）
- 書き出した mp4 の音声末尾に、約 40 ms の無音（AAC のパディング）が動画の終わりより後ろにはみ出ることがある
- タブを閉じる直前 300 ms 以内の編集は、保存されないことがある
- サムネイルの範囲検出は縮小コピーで行うため、非常に大きなレイヤー（約2800px超）の孤立した微小な点は切り抜き範囲から外れることがある
- サムネイルはグループ・レイヤーの不透明度と描画モードを反映しない（グループは中身を合成したもの、レイヤーは画像そのものを出す）
